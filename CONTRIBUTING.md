# Contributing

## Layout

```
src/reeds/
  _client.py      Reeds and AsyncReeds (one client, a property per API module), Webhooks
  _core.py        the HTTP calls, once per flavour: credentials and the token, retries, idempotency keys
  _base.py        what both flavours share: configuration, headers, the retry rules, envelopes
  _errors.py      one exception per kind of failure
  _pagination.py  Page, AsyncPage, AsyncPaginator
  _parse.py       JSON -> models, never failing (validates, else builds leniently)
  _webhooks.py    webhook signatures, the same for every Reeds API
  _events.py      ReedsEvent: every API's events, UnknownEvent for the rest
  shipping/       the Shipping API module: _resources.py (sync), _async_resources.py, _generated.py (types)
scripts/          generate.py: spec/*.yaml -> src/reeds/*/_generated.py
spec/             copies of the APIs' OpenAPI specs, taken from sendx-api by the sync-spec workflow
tests/            pytest, each client test run against Reeds and AsyncReeds; tests/e2e (the real API in
                  Test mode), tests/smoke (real HTTP), tests/frameworks (the README's webhook handlers)
```

The method names match the Reeds Node.js and PHP libraries, in Python's style (`mark_ready`, `list_transactions`), so code reads the same in each language.

## Checks

With [uv](https://docs.astral.sh/uv/):

```sh
uv venv && uv pip install -e . --group dev
pytest                                # unit tests, both clients, and the framework handlers
python tests/smoke/smoke.py           # over real HTTP, with a real timeout and a refused connection
mypy                                  # src/reeds and tests/readme_examples.py, strict
pyright                               # tests/readme_examples.py, strict
ruff check . && ruff format --check .
python scripts/generate.py --check    # the generated types match spec/
```

CI runs these on Python 3.10 to 3.14, with the latest dependencies and with the lowest versions `pyproject.toml` allows (`uv pip install --resolution lowest-direct`). When you raise a dependency's floor, it's because the lowest job failed.

## The README

Every Python block in README.md is checked: `tests/test_readme.py` fails unless it appears word for word in `tests/readme_examples.py` (type-checked) or `tests/frameworks/` (run in real FastAPI, Flask and Django apps). Change both together.

## A spec change

The sync-spec workflow opens a pull request when sendx-api deploys a changed spec to production. `python scripts/generate.py` rebuilds `src/reeds/shipping/_generated.py`. `tests/test_coverage.py` fails until every operation in the spec has a method on both clients. Add the methods (sync and async), a test, a CHANGELOG entry, then merge.

## Adding a Reeds API

1. The API follows the shared rules (path `/<api>/v<n>`, OAuth scope, envelopes, cursor pagination, Idempotency-Key, `Retry-After`, `X-Request-Id`, one webhook format). Its spec is in sendx-api's `openapi/`.
2. Add it to `APIS` in `scripts/generate.py` and to the sync-spec workflow; put its spec in `spec/` and run the generator.
3. Add `src/reeds/<api>/` (sync and async resources), a property on `Reeds` and `AsyncReeds`, its events in `_events.py`, and its operation map in `tests/test_coverage.py`.
4. Add its end-to-end scenario to `tests/e2e/`.
5. Release as a minor version.

## Webhook test vectors

`tests/fixtures/webhook-vectors.json` is generated by sendx-api's own signing code, so the library and the server can't drift. Every Reeds library runs the same file. Don't edit it by hand.

## Releasing

PyPI publishes from git tags through trusted publishing (no token).

1. Update `__version__` in `src/reeds/_version.py` and the CHANGELOG (a test checks the version is the package's).
2. Merge to main once CI is green, then push the tag `vX.Y.Z`. The release workflow builds the sdist and wheel, checks the tag matches the version, and publishes.
3. The first time only: on pypi.org, add a pending trusted publisher for the project `reeds-sdk`: owner `SendX-hq`, repository `reeds-python`, workflow `release.yml`, environment `pypi`. Create the `pypi` environment in the GitHub repository's settings.
